Provena · 12 · Load figures: k6 against the application with the demo data

The targets come from the architecture plan: 99.9 per cent in business hours, RPO 15 minutes, RTO 4 hours, reads under 300 milliseconds at p95. The load figures are measured with k6: the baseline profile of 27 users has a read p95 of 15 milliseconds and a write p95 of 60; the stress profile of 104 users without pauses reached 556 requests a second with no errors. Recovery is a script, not a document: the DR drill backs up, restores, starts the application on the copy and verifies the lot and ledger hash chains. Period end, valuation runs and report exports run outside the request and are polled, so no request holds a connection for minutes; after five transport failures in a row a registry's dispatch pauses until a probe or an operator resumes it. The one rehearsal still open is a drill against a production backup.
