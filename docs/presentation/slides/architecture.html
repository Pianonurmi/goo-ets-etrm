Architecture

One application, nineteen bounded contexts

Provena · 11 · Registry calls go through an outbox, GL exports are exactly-once, events leave only after commit

A modular monolith: one deployable and one database, with the discipline of separate services. Each of the nineteen modules is a bounded context with its own schema and migrations. Another module may only use its published api package, and the build fails on any other dependency. Side effects across modules travel as domain events inside the command transaction; selected events leave for Kafka only after commit. Registry calls never run inside a database transaction: they are written to an outbox first. The web UI is bundled into the same jar, and the OpenAPI document between them is a committed contract.
